# Engineering Review

Author: Hiba Hussieni

## 1. PRD Review

The initial draft required clear completion controls without defining
their exact labels.

I accepted a clarification specifying:
- "Mark complete" for incomplete tasks.
- "Undo completion" for completed tasks.
- Explicit "Incomplete" and "Completed" status text.
- Accessible button names that identify the associated task.

This made the requirement predictable and testable.

It was not applied. The development dependency findings remain unresolved.

## 4. Design Review

The first Stitch design included a "UI State Specification Reference"
section with a disabled demonstration button.

I requested its removal because it exposed design documentation
inside the user interface and added a control with no real action.

The refined desktop HTML was checked and contained neither
"UI State Specification Reference" nor "Specification Sample".

The implementation follows the documented charcoal and crimson
direction, with a threat brief, progress summary, and three task cards.

I compared the desktop implementation with the selected Stitch design.
The appearance was close, and I did not identify a meaningful mismatch
requiring correction.

## 6. Reflection

### How did the PRD prevent an unnecessary feature?

It explicitly excluded login, a database, and task editing.
This kept the first version focused on three predefined tasks
and completion tracking.

### What did the POC test, and what did it not prove?

It tested whether completing, undoing, and repeatedly toggling tasks
kept the count and percentage consistent.
It did not prove product demand or verify the final visual design.

### Why is this MVP useful even though it is small?

It lets Asta see the full training plan, identify unfinished tasks,
and track completion on one screen.

### What did MCP allow the agent to do?

It allowed the coding agent to list Stitch projects and retrieve
desktop screen details, including HTML and screenshot download URLs.
The returned HTML URL was then fetched separately for content checks.

### Which AI-generated decision did I correct?

During review, I accepted explicit completion and undo labels
instead of leaving the controls vaguely specified.
I also requested removal of the unnecessary design-reference section
generated by Stitch.

### Explain the task state and progress calculation.

Each task has a completed boolean.
A functional state update toggles only the selected task.
The completed count is derived by counting completed tasks.
The percentage is Math.round((completedCount / totalTasks) * 100).
Priority does not change a task's weight.
State resets when the page refreshes.

### What remained my responsibility when AI generated code?

I reviewed scope and design decisions, followed the setup,
performed manual checks, examined command results, and documented
limitations. I also collected feedback from my sister.

I remain responsible for understanding the core logic and ensuring
that the submitted work accurately reflects the implementation
and the checks performed.
